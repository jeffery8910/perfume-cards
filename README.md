# 香水卡 Perfume Cards

把疊香筆記做成 IG 輪播字卡的靜態網站。資料是 JSON，版型由網頁自動套用，所以任何品牌都能加。

- **網頁版**：每款香水一張卡，卡片下方可以直接打分數、寫感受，最上面有「我的排行」，最後有自動彙整的評分總表和試香紀錄。分數存在瀏覽器裡，可以匯出／匯入備份。
- **自己疊疊看**（`mix.html`）：任何人都能從網站上所有香水挑 2–3 支，看這組依香材分析出的香氣方向，打分數、寫感受，存成圖片到手機，也能複製連結分享同一組。
- **IG 圖片**：每張卡都能匯出成 1080×1350 PNG，在手機上按「存成圖片」或「整組存到手機」就會跳出分享選單，選「儲存影像」。

## 網站結構

```
index.html                 首頁：列出所有組合
mix.html?p=<香水>,<香水>    自己疊疊看
deck.html?c=<組合檔名>      一組香水卡
editor.html                新增香水、新增組合的表單
data/index.json            首頁要列出哪些組合
data/catalog.json          所有香水的清單（自動產生，給「自己疊疊看」用）
data/perfumes/<品牌>/<香水>.json   一支香水的資料
data/collections/<組合>.json       一組疊香計畫：基底、候選、比較表、評分項目
img/<品牌>/<香水>.jpg       瓶身照
```

一支香水只要建立一次，就能放進不同的組合重複使用。

## 新增一個品牌或一支香水

最簡單的方法是打開網站的 **新增香水** 頁：

1. 填品牌、香水名稱、香材、單獨聞起來的描述，挑一個主色（底色會自動調淡）。
2. 右邊會即時預覽卡片。按 **在 GitHub 建立這個檔案**，GitHub 會開啟新增檔案頁，內容已經填好，按 Commit。
3. 按 **上傳照片**，把瓶身照拖進去，檔名改成表單顯示的名字（例如 `in-green-silence.jpg`）。

也可以直接在 GitHub 上複製一個 `data/perfumes/` 裡的檔案修改。

### 香水資料欄位

| 欄位 | 說明 |
| --- | --- |
| `brand`、`brandZh` | 品牌英文名、中文名 |
| `name`、`en`、`series` | 香水中文名、英文名、系列 |
| `photo` | 照片：自己拍的放 `img/品牌/` 寫相對路徑，或直接貼香水網站上的圖片網址。沒有照片會畫一個瓶子 |
| `photoFit`、`photoBg` | `contain` 讓整支瓶子完整顯示（官網白底圖適合），`photoBg` 是照片底色 |
| `photoCredit`、`link` | 圖片來源名稱、商品頁連結（卡片上會顯示「圖：來源」並連過去） |
| `color` | 主色。可另外指定 `bg`（底色）和 `soft`（標籤色），不填會自動算 |
| `theme` | 填 `dark` 就是深色卡片 |
| `materials` | 香材清單 |
| `notes` | 前中後調：`{"top": [], "heart": [], "base": []}` |
| `materialsNote` | 沒有香材時顯示的說明 |
| `source` | 描述的來源：推論、官方、試香心得 |
| `smell` | 單獨聞起來的感覺 |
| `classification`、`warning`、`sub` | 基底香水卡用的分類、注意事項、副標 |

## 新增一個組合

在 **新增香水** 頁切到 **新增組合**：選基底香水（你固定會疊的）和候選香水，填評分項目，按按鈕建立組合檔。之後在 GitHub 上補每支候選的 `result`（疊起來的結果）、`why`（原因）、`conflict`（可能衝突）、`score`（1–5 的相容性）。

`comparisons` 可以放兩種比較卡：

- `"type": "matrix"`：多欄圓點比較表（`columns`、`rows[].values`，`null` 代表資料不足）
- `"type": "list"`：幾支香水的文字比較（`items`、`warning`）

最後到 `data/index.json` 加一行，首頁就會出現。範例請看 `data/collections/tea-juniper.json`。

## 香水照片

照片有四種來源，在「新增香水」頁選：

1. **香水網站的圖片**：貼上品牌官網商品圖的網址。圖片是直接嵌入對方網站的檔案，不會複製進這個儲存庫，卡片右下角會標「圖：來源名稱」並連回商品頁（`photoCredit`、`link`）。
2. **Fragrantica**：貼 Fragrantica 的商品頁網址，網址最後的數字會自動換成它的商品圖，並註明來源。
3. **自己拍的**：選照片後按「下載整理好的照片」，會縮成適合網頁的大小、用正確檔名存好，再上傳到 `img/品牌/`。這是最穩、也最沒有版權疑慮的做法。
4. **先不放**：卡片會依主色畫一個瓶子。

另外，**每個看網站的人都能在卡片上按「用我的照片」**，換成自己拍的瓶身照。這張照片只存在他自己的瀏覽器，不會上傳，存成圖片時會標「圖：我拍的」；按「還原」換回網站圖片。

嵌入的網站圖片可能被對方換掉或移除。GitHub Actions 每次匯出圖片前會先檢查所有照片連結，讀不到的會列在執行紀錄裡；在自己電腦可以跑 `npm run check-photos`。

## 「自己疊疊看」怎麼分析

每支香水的香材（`materials` 和 `notes`）會依關鍵字分到柑橘、綠意、茶、花香、木質、琥珀樹脂、海洋、麝香、苔土、甜美、辛香等類別，每支香水佔一樣的比重，算出這組的香氣方向；兩支以上都有的類別會標成「共同的橋梁」。這是依文字分類，不是實際試香，所以卡片上會註明。分類規則在 `assets/mix.js` 的 `FAMILIES`，可以自己增減關鍵字。

新增香水後，GitHub Actions 的「更新香水清單」會自動更新 `data/catalog.json`，「自己疊疊看」就會出現新香水。在自己電腦可以跑 `npm run catalog`。

## 匯出 IG 圖片

**在網頁上**：每張卡下方有「存成圖片」，標題下有「整組存到手機」。手機會跳出分享選單（選「儲存影像」存進相簿），電腦會直接下載。其他網站的圖片會經過 images.weserv.nl 轉一手才能畫進圖片裡。

**自動**：推上 GitHub 後，Actions 會跑「匯出 IG 圖片」。到儲存庫的 **Actions** → 最新一次執行 → 最下面 **Artifacts** 下載 `ig-cards.zip`，裡面每個組合一個資料夾，照 01、02… 的順序上傳 IG。也可以在 Actions 頁按 **Run workflow** 手動重跑。

**在自己電腦**：

```bash
npm install
npx playwright install chromium
npm run shots                 # 全部組合
npm run shots -- tea-juniper  # 只匯出一組
```

圖片在 `shots/` 資料夾。如果某張卡的字太多、超出 1080×1350，終端機會提醒是哪一張。

## 在自己電腦預覽

網頁用 `fetch` 讀 JSON，直接雙擊 HTML 會讀不到，要開一個本機伺服器：

```bash
npx serve .
```

## 開啟 GitHub Pages

儲存庫 **Settings → Pages → Build and deployment**，Source 選 **Deploy from a branch**，分支選 `main`、資料夾選 `/ (root)`。幾分鐘後網址會是 `https://<帳號>.github.io/<儲存庫>/`。

## 注意

- 評分和試香紀錄只存在你自己的瀏覽器，不會上傳到 GitHub。換手機或清除瀏覽資料前，先按「匯出備份」。
- 標示「推論」的內容是依公開香調描述的主觀預測，不是實際試香結果。
- 公開的儲存庫任何人都看得到。目前香水照片是直接連到品牌官網（NOSEWAY）和 Fragrantica 的圖片網址，沒有複製進這個儲存庫；對方網站換圖或移除時，卡片會顯示「圖片載入失敗」，換成自己拍的照片最穩。
- 雅聞倍優綠茶 13 還沒有照片，暫時用畫出來的瓶子代替。
